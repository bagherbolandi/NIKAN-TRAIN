# اعتبارسنجی نسخه ۰٫۸ — مدیریت شرکت‌ها

تاریخ: ۲۰۲۶/۱۰/۱۶ به وقت تهران. محیط اجرا Linux، Python 3.12.14 و Chromium واقعی است. نسخه نصب هر دو بسته مستقل و سرور `0.8.0` است.

## رفتار نهایی

ادمین هلدینگ از «مدیریت سامانه ← مدیریت شرکت‌ها» می‌تواند شرکت جدید اضافه کند، نام شرکت را تغییر دهد و شرکت خالی را حذف کند. نام تکراری یا نام خالی رد می‌شود. کاربران شرکت‌ها این منو را نمی‌بینند و درخواست مستقیم آنان به API مدیریت شرکت‌ها نیز رد می‌شود.

ویرایش نام، شناسه و ارتباط پرسنل، دوره‌ها، سوابق و لوگوی شرکت را حفظ می‌کند. شرکت دارای داده وابسته یا هر نوع کاربر، حتی غیرفعال، حذف نمی‌شود و پیام مشخص دریافت می‌کند. حذف شرکت خالی فقط لوگوی همان شرکت را پاک می‌کند؛ رویدادهای حسابرسی باقی می‌مانند و شناسه حذف‌شده دوباره به شرکت دیگری اختصاص نمی‌یابد.

فهرست انتخاب شرکت و نام سربرگ پس از تغییر به‌روز می‌شوند. حذف شرکت انتخاب‌شده، شرکت معتبر بعدی را انتخاب و اطلاعات موقت مربوط به شرکت قبلی را پاک می‌کند. با حذف همه شرکت‌های خالی، ادمین همچنان می‌تواند وارد شود و نخستین شرکت جدید را ثبت کند؛ نام شرکت‌های اولیه دوباره ساخته نمی‌شود.

## بررسی بسته‌ها

هر دو EXE واقعی با NSIS ساخته شدند. Python رسمی 3.13.16 و RECORD وابستگی‌ها پیش از ساخت بررسی شدند. پس از استخراج، SHA256 تمام ۱۷۸۲ فایل manifest مستقل و ۲۰۲۱ فایل شبکه تأیید شد. سورس بسته‌ها با سورس نهایی برابر است و ماژول `companies.py` و رابط `companies.js` داخل هر دو بسته هستند. داده محلی، کلید خصوصی و کاربر بهره‌برداری در نصاب‌ها قرار ندارند.

[اندازه و SHA256 بسته‌ها](build-verification-0.8.json)، [نتیجه اجرای کد استخراج‌شده](payload-tests-0.8.json).

اعتبارسنج مستقل روی برنامه استخراج‌شده با وابستگی‌های مخصوص نسخه مستقل اجرا شد؛ مدیریت شرکت‌ها، محافظت از داده، نقش‌ها، آموزش‌ها، پشتیبان SQLite و شروع/توقف واقعی `desktop.py` موفق بود. دو جریان مرورگر مدیریت شرکت‌ها و حذف همه شرکت‌های خالی/ساخت شرکت نخست نیز روی همین برنامه استخراج‌شده موفق بودند.

اعتبارسنج شبکه روی سرور HTTPS واقعی با تأیید گواهی اجرا شد؛ مدیریت شرکت‌ها و محدودیت نقش‌ها، ۱۶ ثبت هم‌زمان، تقویم و برنامه‌ریزی، پشتیبان رمزگذاری‌شده، بازیابی پرسنل، رمزها، پیوست‌ها، شناسنامه و رجیستری شرکت‌ها موفق بود. سرور پس از آزمون به‌درستی متوقف شد.

نصاب میانبر کلاینت تغییری در منطق سامانه ندارد و نسخه محصول آن همچنان `0.5.0` است. برای به‌روزرسانی شبکه، نصاب سرور را ارتقا دهید.

## ارتقا و محدوده تأیید

رجیستری تک‌ردیفی شرکت‌ها یک جدول افزوده است؛ جدول‌های قبلی هنگام مهاجرت بازنویسی نمی‌شوند. ثبت شرکت‌های پیش‌فرض فقط برای پایگاه کاملاً جدید انجام می‌شود. [بررسی ارتقای ۰٫۷ به ۰٫۸](upgrade-0.7-to-0.8.json) حفظ داده‌های جدول‌های قبلی را جداگانه ثبت می‌کند.

اجرای برنامه استخراج‌شده با Python روی Linux، اجرای خود نصاب یا runtime ویندوز نیست. نصب واقعی ۰٫۸، Scheduled Task، shortcut و ارتقا/حذف نصب روی Windows در این محیط اجرا نشده‌اند. workflow ویندوز موجود است، اما پیکربندی آن و گزارش نسخه‌های قدیمی مدرک موفقیت اجرای این ساخت جدید نیستند.

راهنمای شروع محیط (`start_skill`) برای مسیر پروژه، آزمون‌های فعلی و ساخت نصاب در پیش‌نویس تنظیمات محیط ذخیره شد؛ اسکریپت نصب و الزامات شبکه/رازها تغییر نکردند. این ذخیره به معنی انتشار محیط ابری نیست و از انتشار برنامه در GitHub جداست.
